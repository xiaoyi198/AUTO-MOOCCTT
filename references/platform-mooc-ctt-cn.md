# 平台实测存档：中国烟草网络学院（mooc.ctt.cn）

对应适配器：`scripts/adapters/mooc-ctt-cn.js`。以下均为 **2026-09-29 / 09-30 在本机实测**所得，
不是推测。换机器验证时对照本表，若某项不再成立，先怀疑平台改版。

## 一、登录入口

SPA（hash 路由）。首页右上角"登录"是一个 `<div class="text-color">` **叶子节点**。
- ❌ 不能用 `innerText` 匹配父容器：会命中 `.header` 大容器，其 `getBoundingClientRect()` 是 `0,0`
- ✅ 正确做法：筛出 `innerText === '登录'` **且无子元素**的节点，按面积升序取最小者，
  再用 `page.mouse.click(cx, cy)` 按坐标点击（`probe.js click "登录" --exact` 即此逻辑）
- 点击后跳转 `https://mooc.ctt.cn/oauth/#login/<base64>`，页面含 APP 扫码登录 + 账号密码登录

## 二、路由

**一律点顶部导航跳转，不要手改 hash —— 猜的 hash 会白屏。**

| 目标 | 进入方式 | 落地 hash |
|---|---|---|
| 专题目录 | 点导航「专题」 | `#/study/subject/index` |
| 课程目录 | 点导航「课程」 | `#/study/course/index` |
| 个人中心 | 头像下拉「学习中心」 | `#/center/index` |
| 我的主页 | 直接访问 | `#/home` |

❌ 无效路由（白屏）：`#/subject/list`、`#/course/list`

## 三、学时面板（零打扰读取）

**全局页头里就有，不用点头像、不用开新页**，学习页和专题页都能读到：

```js
const self    = document.querySelector('.credit-label').innerText; // "50 / 12.5 网络自学（时）"
const central = document.querySelector('.hour-label').innerText;   // "90 / 30.0 集中培训（时）"
```

格式是 **「要求 / 已完成」**（`50 / 12.5` = 要求 50、已完成 12.5），**不是**「已获/要求」。
⚠️ 上例数字是演示值，实际以你自己面板读数为准。

判定依据（不是猜的）：
1. 先和用户确认「要凑的就是右上角那两个学时口径」→ 首位数字是**要求**。
2. 再用一组已知的历史数据交叉验证：`当前读数 = 历史值 + 本次新增`，且「本次新增」应等于
   这段时间里学完的专题页标注学时之和。对得上，才能确定首位是要求。

ℹ️ **两个口径的结算时机不同**：`网络自学` 随观看进度持续增长（不必等专题完成）；
`集中培训` 只在**「网络专题培训」类专题整体完成**时一次性进账。所以学到一半时看到某个口径纹丝不动，
先分清是"还没到结算点"还是"这类专题根本不进这个口径" —— 见第四节。

## 四、结算规则（修正版：按专题**类型**分账，不是按完成状态）

| 专题页标注的「专题类型」 | 完成后计入 |
|---|---|
| **网络专题培训** | **集中培训（时）** —— 按专题声明学时**一次性全额**进账 |
| **网络自学** | **网络自学（时）** —— 只按观看进度累计；完成时「集中培训」不动 |

⚠️ 本文件早期版本写的是「学完整专题 → 集中培训；留尾 → 网络自学」，**那是错的**：
它把"完成状态"当成了分账依据。修正依据（这类结论必须用数据证实，别用直觉）：

| 观测量 | 结果 |
|---|---|
| 某「网络专题培训」专题（声明 25.4 学时）完成 | 「集中培训」恰好 +25.4 |
| 两个「网络自学」专题（16.3 / 36.8 学时）完成，平台均显示"已完成" | 「集中培训」**纹丝不动** |

四条实践含义：

1. **要补哪个口径，就只学那个口径对应的专题类型。** 拿「网络自学」类专题去补「集中培训」缺口
   是纯浪费 —— 实测有一个 25.4 学时的网络自学类专题挂到一半，才发现它对缺口零贡献，
   只能主动收尾切换（放弃动作必须按铁律 6 显式打日志）。
2. 排期输入里给每个专题标 `contributesTo`（口径 key），比靠"完成/留尾"推导可靠得多。
3. 「留尾」技巧只在**按完成状态分账**的平台上才有意义；在本平台不用它，更不要用它去凑另一个口径。
4. 学时按**专题声明学时**结算，与逐帧观看时长无关 → 挑「学时 ÷ 实际视频时长」高的专题最划算。

### 怎么自己复核（换机器 / 平台改版后必做）

1. 引擎每轮把面板读数写进 `credit-history.jsonl`（变化才写，带时间戳）。
2. 取一个时间窗，列出「窗内变成完成态的专题」及其**类型**与声明学时。
3. 拿读数增量去对：对得上哪个类型，规则就是哪个。**对不上就说明还有别的因素**
   （例如专题报名状态、年度计划归属），继续查，不要硬套本文档。

选课优化：示例比值（请换成你自己的实测值）—
示例专题 20/14.6 h ≈ **1.37**、示例专题 5.6/4.9 h ≈ 1.14、示例专题 5.6/5.4 h ≈ 1.04。

## 五、修别门槛

专题页「必修N门」那一行若写 `选修M门 (X学时；完成0学时以上)`，
意味着**选修门槛是 0 学时，选修完全不用做**。

实测例：某专题页面标「必修 2 门 6.1 学时／选修 14 门 17.8 学时」。
盲学全部会白耗 17.8 学时（约 18 小时）。⇒ `eligibleHours = 6.1`，不是 23.9。

## 六、课程完成判定

`video.ended || currentTime / duration >= 0.995`。
完成后 `page.close()` 关掉旧学习页，回专题页点下一门。

## 七、登录态失效的识别

URL 里出现 `oauth` 即判定为登录态失效，**无法自愈**（没有账号密码），必须通知人工重新登录。

## 八、已知的坑（本平台特有）

| 现象 | 原因 | 处理 |
|---|---|---|
| 视频莫名中断，SPA 跳到 `#/study/errors/<courseId>` | Edge 睡眠标签页把后台学习页挂起 | 启动加 `--disable-features=SleepingTabs`；只读 DOM 侦察，别开多余标签 |
| 读到没有 `<video>` 的页面 | 探索留下的废弃 `course/detail` 页被优先选中 | 用当前专题 UUID 精确匹配 + 打分选页 |
| 点"开始学习"点到了别的专题 | `subject/detail` 选错专题页 | 同上：UUID 精确匹配 |
| 脚本报"找到目标"但页面无反应 | 只打标记没真点击 | 见 references/writing-an-adapter.md 第三节 |
| 切专题时报 `empty-course-list`（解析不到课程列表） | 页面还没渲染完 / 登录态失效 / 该专题入口文案变了 | 引擎会重试一次，仍失败就记 `failed` 跳下一个（不终止整条链）。**新专题上线后务必单跑一轮确认能起播**；连续多个专题都这样，先查登录态与适配器选择器 |
| 学时读数长时间不涨 | 可能只是"这类专题不进这个口径"（见第四节），不是卡住 | 先按第四节复核归集规则，再看 `evidence/latest/status.json` 的视频是否在推进 |
